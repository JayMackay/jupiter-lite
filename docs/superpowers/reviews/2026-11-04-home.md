## 2. Brainstorm: text in shapes (fixed, root causes found)

Changed: `src/components/BrainstormBoard.tsx`, `src/styles/whiteboard.css`. Test: `dashboard-ui.mjs`.

Reproduction (Edge, scratch scripts): a double click opened the editor and typing worked in every shape kind
(rectangle, ellipse, diamond, triangle), at several sizes, after move, resize, fill, zoom, with jitter between
clicks, slow clicks and touch double taps. So the editor itself was not broken. What was wrong:

1. No other way in. Drawing a shape selects it, but typing, a single click and Enter did nothing; only a double click
   worked and nothing says so. Anyone who just types after drawing sees "cannot write text".
2. Text did not sit inside ellipses, diamonds and triangles. Their padding was in percent, which resolves against
   the width of the containing block, and that is `.jh-bd-world`, which is 0px wide. So the padding was always 0 and
   the text spanned the whole box, over the outline (`shape-text-before.png`).
3. Escape in the editor also closed the whole Brainstorm window (the Dashboard listens for Escape on `window`).

Fix
- A selected note or shape opens its editor when you press Enter or F2 or just start typing; the typed letter is kept
  (`flushSync` mounts and focuses the editor before the next key, so fast typing loses nothing). Buttons, menus and
  inputs keep their keys. Placeholder "Type here". Caret goes to the end.
- Shape text lives in `.jh-bd-shape-body`, an absolute box inset by percentages of the shape itself (ellipse 15%,
  diamond 26%, triangle 46% 25% 8%, rectangle 12px). Long text wraps to that width and is never clipped.
- Escape in the editor stops propagating, so it only leaves the editor.

Evidence: red first (`dashboard-ui.mjs` timed out waiting for the editor after typing), green after. Checks: drawing
does not open an editor by itself; typing starts it with the first letter; Backspace edits the text and does not delete
the shape; Enter commits; the text box stays at least 10% inside the ellipse on every side; Enter reopens the editor;
Escape closes only the editor and the Brainstorm window stays; text is saved in the board JSON and is still on the
board after switching to another board and back. Screenshots: `shape-text-before.png`, `shape-text-after.png`,
`test-board-shape-text.png`, `test-board-shapes.png`.

## 4. Flashing white line in the Brainstorm card (not reproduced, no code change)

Method: `Page.captureScreenshot` of the card region in a loop (about 25 frames a second, `fromSurface`) and a CDP
screencast of the whole viewport (about 40 frames a second), decoded with pngjs. About 8,900 frames in all. A frame is flagged when a column
inside the card has more than 30% of its rows brighter than luma 150 (a vertical line), or changes by more than 50
luma in 30% of its rows between frames.

| Runs | Frames | Result |
| --- | --- | --- |
| Idle 12 to 40 s, DPR 1, 1.25 and 2; windows 1600x1000 and 1990x1580; Chats open and hidden | 2,297 | none |
| Pointer moving over and across the card (DPR 1.25 and 1.5, with and without ideas on the board) | 1,978 | none |
| Wheel scrolling the page (1,221 frames; 838 of them in a short window where the page really scrolls) | 1,221 | none |
| Voice "show my news" cycles (orb speaking) | 653 | none |
| Open and close the To do window repeatedly | 1,189 | 20 flagged in one run, all the card fading as a whole (opacity transition), no thin line |
| Window resizes | 401 | none (the orb canvas is cleared on each resize, 36 resets, no visible line) |
| Screencast, pointer moving over the card | 1,204 | none, worst column 5.7% (text) |

Ruled out
- Elements: no element 4px wide or less and 60px or taller anywhere on Home; only the canvas, vignette and the card's own
  glass layers sit behind or over the card.
- Orb canvas resets: 2 or 3 at start, none while idle.
- The old editable prompt's blinking caret (the first screenshot shows one): the Brainstorm card is the fourth of four
  columns, and the caret of a centred empty field sits at the middle of the Dashboard, which in the report screenshot
  is off screen to the left. A caret is also about 54px tall, not the whole card. Ticket 1 removes that caret anyway.
- Glass cards, clock re-render every second, News rotation: nothing visible in the frames.

What is still open
- It was not caught here, so no fix was made. The unproven suspect is GPU compositing at fractional display scaling
  (at 125% the card sits on a half pixel, for example x 1492.5 device px) with `backdrop-filter` over the orb canvas,
  which redraws 30 times a second. That would show in the Tauri WebView2 window only. A 60 Hz screen recording of the
  real app, the Windows display scale and GPU would settle it.
- Cheap A/B if it returns: temporarily set `backdrop-filter: none` on `.jupiter-home .jh-glass` (or give `.jh-core-wrap`
  `will-change: transform`) in the built app and see whether the line disappears.
